# AI 运维平台核心业务流程图

## 1. 文档概述

### 1.1 文档目的

本文档基于《AI 运维平台项目工程需求文档》《AI 运维平台信息架构》和《AI 运维平台页面原型》，梳理 AI 运维平台的核心业务流程，并以流程图形式描述关键业务链路。

本文档用于指导产品评审、技术架构设计、前后端接口拆分、权限与审计设计、自动化执行设计和后续研发排期。

### 1.2 流程设计原则

- 所有高风险动作必须先确认，后执行。
- AI 负责分析、建议和生成计划，不直接绕过平台执行真实操作。
- 用户权限、资源范围、风险等级必须在执行前校验。
- 告警、资源、日志、指标、变更、工单、知识库之间需要形成上下文闭环。
- 所有关键行为必须写入审计日志。
- 执行失败必须给出失败原因，并支持重试、回滚或人工接管。

### 1.3 图示说明

本文档中的流程图采用 Mermaid 语法，可在支持 Mermaid 的 Markdown 工具中直接渲染。

## 2. 平台总体业务闭环

### 2.1 流程说明

AI 运维平台的总体闭环是：用户或系统发现问题，平台聚合上下文，AI 辅助分析，用户确认方案，平台执行动作，记录结果并沉淀知识。

### 2.2 流程图

```mermaid
flowchart TD
    A[系统运行数据] --> B[平台统一接入]
    B --> C[首页驾驶舱展示全局态势]
    B --> D[告警中心接收告警]
    B --> E[资源与应用展示状态]
    B --> F[日志与指标查询]

    C --> G[用户发现风险]
    D --> G
    E --> G
    F --> G

    G --> H[发起 AI 分析]
    H --> I[平台聚合上下文]
    I --> I1[指标]
    I --> I2[日志]
    I --> I3[告警]
    I --> I4[资源]
    I --> I5[变更]
    I --> I6[知识库]

    I --> J[AI 输出分析结论]
    J --> K[AI 给出处置建议]
    K --> L{是否需要执行动作}

    L -- 否 --> M[创建工单或沉淀知识]
    L -- 是 --> N[生成执行计划]
    N --> O[权限与风险校验]
    O --> P[执行确认页]
    P --> Q{用户是否确认}

    Q -- 否 --> R[取消任务]
    Q -- 是 --> S[执行编排服务执行]
    S --> T{执行是否成功}

    T -- 是 --> U[记录执行结果]
    T -- 否 --> V[失败处理]
    V --> V1[重试]
    V --> V2[回滚]
    V --> V3[人工接管]

    U --> W[写入审计日志]
    V --> W
    W --> X[生成事件总结]
    X --> Y[沉淀知识库]
```

```mermaid
    C --> C2[应用]
    C --> C3[资源]
    C --> C4[日志]

    D --> H[查询最近变更]
    D --> I[查询历史事件]
    D --> J[查询知识库]

    E --> K[构建 AI 分析上下文]
    F --> K
    G --> K
    H --> K
```

### 4.2 流程图

```mermaid

    H --> J[通知相关负责人]
    I --> J
    J --> K{用户是否认领}
    K -- 否 --> L[保持新建状态]
    K -- 是 --> M[告警状态变为已认领]

    M --> N[用户点击 AI 分析]
    N --> O[聚合指标/日志/变更/历史事件]
    O --> P[AI 输出分析结论与建议]
    P --> Q{是否需要执行处置}

    X --> Y[生成处理记录]
    Y --> Z[可选生成复盘或知识文档]
```

## 5. AI 生成执行计划流程

### 5.1 流程说明

AI 可以根据用户问题、告警上下文或资源状态生成执行计划，但不能直接执行。执行计划必须进入平台任务系统并进行权限、风险和人工确认。

### 5.2 流程图

```mermaid
flowchart TD
    A[用户请求 AI 给出处置方案] --> B[AI 分析上下文]
    B --> C[AI 生成推荐操作]
    C --> D{推荐操作是否可执行}

    D -- 否 --> E[仅展示建议和排查步骤]
    D -- 是 --> F[生成执行计划草稿]

    F --> G[平台解析执行动作]
    G --> H[识别目标资源]
    G --> I[识别操作类型]
    G --> J[识别输入参数]
    G --> K[识别回滚方案]

    H --> L[权限校验]
    I --> L
    J --> L
    K --> L

    L --> M{权限是否通过}
    M -- 否 --> N[拒绝创建任务并提示无权限]
    M -- 是 --> O[风险等级评估]

    O --> P{风险等级}
    P -- 低风险 --> Q[创建可直接执行任务]
    P -- 中风险 --> R[创建待确认任务]
    P -- 高风险 --> S[创建待审批任务]
    P -- 极高风险 --> T[创建多级审批任务并要求回滚方案]

    Q --> U[进入执行确认页]
    R --> U
    S --> V[进入审批流程]
    T --> V

    V --> W{审批是否通过}
    W -- 否 --> X[任务结束: 审批拒绝]
    W -- 是 --> U

    U --> Y[用户确认执行]
    Y --> Z[执行编排服务执行]
```

## 7. 自动化执行流程

### 7.1 流程说明

自动化执行流程负责执行脚本、API 操作、Kubernetes 操作、云平台操作或任务编排。

### 7.2 流程图

```mermaid
flowchart TD
    A[任务进入执行队列] --> B[执行编排服务领取任务]
    B --> C[加载任务步骤]
    C --> D[选择执行代理或适配器]
    D --> E[执行前校验]
    E --> E1[资源状态校验]
    E --> E2[权限二次校验]
    E --> E3[参数合法性校验]
    E --> E4[风险规则校验]

    E1 --> F{校验是否通过}
    E2 --> F
    E3 --> F
    E4 --> F

    F -- 否 --> G[任务失败]
    G --> H[记录失败原因]
    H --> I[通知用户]

    F -- 是 --> J[按步骤执行]
    J --> K[实时写入执行日志]
    K --> L{当前步骤是否成功}

    L -- 是 --> M{是否还有下一步}
    M -- 是 --> J
    M -- 否 --> N[任务执行成功]

    L -- 否 --> O[任务执行失败]
    O --> P{是否支持自动回滚}
    P -- 否 --> Q[提示人工接管]
    P -- 是 --> R[生成回滚确认]
    R --> S{用户是否确认回滚}
    S -- 否 --> Q
    S -- 是 --> T[执行回滚]

    N --> U[写入执行结果]
    T --> U
    Q --> U
    U --> V[写入审计日志]
```

### 7.3 指定执行介体流程（P1+）

该流程用于 AI 分析后给出建议，运维人员确认后，通过指定介体执行诊断命令或处置步骤。

```mermaid
flowchart TD
    A[AI 生成建议和执行计划] --> B[匹配 Command Spec]
    B --> C{参数 schema 是否通过}
    C -- 否 --> D[拒绝创建执行任务]
    C -- 是 --> E[选择执行介体]

    E --> E1[跳板机/诊断 VM]
    E --> E2[目标机器]
    E --> E3[K8s 诊断 Pod]
    E --> E4[云厂商受控命令通道]

    E1 --> F[创建 Execution Task]
    E2 --> F
    E3 --> F
    E4 --> F

    F --> G[风险评估]
    G --> H{是否需要人工确认}
    H -- 是 --> I[执行确认页展示介体/命令/风险/回滚]
    H -- 否 --> J[进入待执行]
    I --> K{运维人员是否输入 CONFIRM}
    K -- 否 --> L[任务取消或保持待确认]
    K -- 是 --> J

    J --> M[Execution 分发任务]
    M --> N[执行代理领取租约]
    N --> O[执行受控命令]
    O --> P[实时回传 stdout/stderr]
    P --> Q[回传 exit_code 和结果摘要]
    Q --> R[写入执行结果/审计/时间线]
```

关键约束：

- AI 只能生成计划和参数，不能直接执行命令。
- 运维人员必须能看到并确认执行介体、命令规格、参数、风险和影响范围。
- 执行代理只能领取 `pending_execute` 任务。
- 禁止未匹配 Command Spec 的自由命令直接执行。
- 日志回传必须脱敏，服务端必须二次脱敏。

## 13. 权限校验流程

### 13.1 流程说明

平台所有敏感访问和操作都必须经过权限校验，AI 工具调用也必须继承当前用户身份权限。

### 13.2 流程图

```mermaid
flowchart TD
    A[用户发起请求] --> B[身份认证]
    B --> C{是否已登录}
    C -- 否 --> D[跳转登录]
    C -- 是 --> E[读取用户角色与权限]

    E --> F[识别请求类型]
    F --> F1[页面访问]
    F --> F2[数据查询]
    F --> F3[操作执行]
    F --> F4[AI 工具调用]

    F1 --> G[菜单权限校验]
    F2 --> H[数据权限校验]
```

## 20. 云厂商只读接管与观测智能体巡检流程（P1+）

### 20.1 流程说明

该流程描述平台从华为云、其他云厂商、Signoz 等系统获取只读观测数据，并由观测智能体持续巡检、生成证据化建议的后续演进链路。该流程不替代 P0 告警闭环，而是在资源、指标、日志、链路和告警上下文更完整后，增强 AI 分析质量。

安全边界保持不变：Agent 只读观察和建议，真实变更必须进入 Execution。

### 20.2 流程图

```mermaid
flowchart TD
    A[管理员创建只读接入账号] --> B[Integration 保存凭据引用]
    B --> C[连通性测试与能力发现]
    C --> D{账号是否可用}
    D -- 否 --> E[记录失败原因和审计]
    D -- 是 --> F[资源同步 Worker]

    F --> G[Provider Adapter 拉取云资源]
    G --> H[归一化应用/资源/拓扑]
    H --> I[更新 Asset 注册表和拓扑快照]

    I --> J[Inspection Scheduler 触发巡检]
    J --> K[加载巡检策略和目标范围]
    K --> L[查询指标]
    K --> M[查询日志]
    K --> N[查询链路]
    K --> O[查询历史告警和变更]

    L --> P[生成 EvidenceRef]
    M --> P
    N --> P
    O --> P

    P --> Q[Agent 构造脱敏分析上下文]
    Q --> R[AI 分析瓶颈/故障/容量/风险]
    R --> S[生成 Finding 和 Recommendation]
    S --> T{是否需要对外通知}
    T -- 是 --> U[Notification 发送建议]
    T -- 否 --> V[Dashboard/建议中心展示]
    U --> V

    V --> W{是否需要执行动作}
    W -- 否 --> X[沉淀巡检记录和知识]
    W -- 是 --> Y[从建议创建 Execution Task]
    Y --> Z[进入执行确认流程]
```

### 20.3 关键约束

- Integration 凭据不进入 AI Prompt、日志、审计明文和前端持久化状态。
- Provider Adapter 只实现只读查询；写操作必须走 Execution。
- Observability 查询必须产生证据引用，便于审计和复盘。
- Inspection 运行允许 `partial`，外部数据源部分失败时不能影响已采集证据。
- Recommendation 转 Execution 时，中高风险动作必须进入 `pending_confirm`。

详细设计见 `docs/cloud-observability-agent-roadmap.md` 和 `ops/cloud-observability-contract.md`。

## 21. 流程总结

AI 运维平台的核心业务流程以“问题发现、上下文聚合、AI 分析、人工确认、安全执行、审计追溯、知识沉淀”为主线。

其中，第一阶段应优先实现以下四条关键闭环：

1. 告警接入与告警详情闭环。
2. AI 分析与执行计划生成闭环。
3. 执行确认与自动化执行闭环。
4. 执行结果、审计记录与知识沉淀闭环。

平台必须始终坚持：AI 可以分析和建议，但不能绕过权限、风险评估和人工确认直接执行高风险动作。
