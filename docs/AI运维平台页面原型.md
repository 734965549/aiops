# AI 运维平台页面原型

## 1. 文档概述

### 1.1 文档目的

本文档基于《AI 运维平台项目工程需求文档》和《AI 运维平台信息架构》，输出 AI 运维平台的低保真页面原型说明，用于指导后续 UI 视觉设计、前端页面开发、交互设计和产品评审。

本文档重点描述页面布局、核心区域、关键字段、主要操作和页面跳转关系，不包含最终视觉样式和具体组件实现。

### 1.2 原型范围

本页面原型覆盖第一阶段核心页面：

- 登录页。
- 首页驾驶舱。
- AI 运维助手页。
- 告警列表页。
- 告警详情页。
- 应用列表页。
- 应用详情页。
- 资源列表页。
- 资源详情页。
- 日志查询页。
- 指标查询页。
- 自动化执行任务列表页。
- 执行确认页。
- 执行任务详情页。
- 知识库列表页。
- 知识文档详情页。
- 审计中心页。
- 系统管理页。

### 1.3 原型约定

- 页面采用 Web 管理后台布局。
- 默认结构为左侧导航 + 顶部全局栏 + 主内容区。
- AI 助手支持独立页面和全局浮层两种入口。
- 高风险操作必须进入执行确认页。
- 所有执行动作完成后必须关联审计记录。

## 5. AI 运维助手页原型

### 5.1 页面目标

通过自然语言让用户查询状态、分析告警、定位问题、生成执行计划和创建待确认任务。

### 5.2 页面布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ AI 运维助手                                      新建会话  会话历史  设置       │
├───────────────┬──────────────────────────────────────────┬───────────────────┤
│ 会话列表        │ 当前会话                                  │ 上下文与工具        │
│ - 生产告警分析   │                                          │ 当前上下文          │
│ - CPU 异常排查   │ 用户：帮我分析 payment-service 告警        │ - 应用              │
│ - 发布风险评估   │                                          │ - 告警              │
│                │ AI：                                      │ - 时间范围          │
│                │ 结论摘要                                  │                   │
│                │ 分析依据                                  │ 可用工具            │
│                │ 影响范围                                  │ - 查询指标          │
│                │ 推荐操作                                  │ - 查询日志          │
│                │ 风险等级                                  │ - 查询资源          │
│                │ [生成执行计划] [创建工单] [沉淀知识]        │ - 创建待确认任务     │
│                │                                          │                   │
│                │ 输入框：请输入你的问题...                  │ 引用数据            │
└───────────────┴──────────────────────────────────────────┴───────────────────┘
```

### 5.3 AI 回答结构

```text
结论摘要
- 当前告警可能由实例 CPU 持续升高导致。

分析依据
- payment-service 最近 30 分钟 CPU 使用率超过 85%。
- error 日志出现大量 timeout。
- 最近 1 小时存在一次配置变更。

影响范围
- 影响订单支付链路。
- 当前影响 3 个实例。

推荐操作
1. 查看异常实例日志。
2. 临时扩容 2 个实例。
3. 检查最近配置变更。

风险等级：中风险
是否需要人工确认：是

操作按钮：[生成执行计划] [查看日志] [查看指标] [创建工单]
```

### 5.4 关键交互

- 用户输入自然语言问题。
- AI 自动引用当前页面上下文。
- 用户点击引用来源可跳转到对应页面。
- 涉及执行动作时，只能创建待确认任务。
- 用户可对 AI 回答进行有效或无效反馈。

### 7.3 关键操作

### 15.5 P1+ 执行介体确认信息

当 AI 分析结果需要到某台虚拟机、跳板机、Kubernetes Pod、云厂商 Run Command 通道或问题点机器上继续排查/处理时，执行确认页必须额外展示“执行介体”信息。页面不能提供自由命令输入框，只能展示后端已生成并校验通过的 Command Spec 与参数。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 执行介体                                                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│ 执行模式：agent_command                                                     │
│ 介体：prod-jumpbox-01 / jumpbox / 生产 / 华东一区                            │
│ Agent 状态：online，最近心跳 12 秒前，能力：shell.readonly、linux.diagnose    │
│ Command Spec：linux.top_processes@v1                                         │
│ 参数：limit=20，sort=cpu                                                     │
│ 风险等级：低风险；超时：30 秒；输出脱敏：secret/token/password               │
│ 约束：确认后由 Execution Agent 领取租约执行；AI 和前端都不能直接下发命令。     │
└─────────────────────────────────────────────────────────────────────────────┘
```

交互约束：

- 介体必须来自 `exec_medium` 注册表，并通过环境、数据范围、网络区域、Agent 健康状态过滤。
- Command Spec 必须来自后端白名单，包含参数 schema、风险等级、超时、输出脱敏策略和允许介体类型。
- 生产环境写操作、重启、扩缩容、变更配置等命令默认至少为 `medium` 风险，必须进入 `pending_confirm`。
- 用户确认的是“在指定介体上执行指定 Command Spec 与参数”，而不是确认一段未受控的自由文本命令。
- 确认后任务仍进入 Execution 状态机，由 Agent 通过租约领取；页面不得绕过 `pending_confirm -> pending_execute -> running -> success|failed`。

## 25. 页面原型总结

AI 运维平台页面原型应围绕“看状态、问 AI、查上下文、生成计划、确认执行、追踪结果、沉淀知识”的主路径设计。

第一阶段最重要的页面闭环是：

```text
首页驾驶舱 → 告警详情 → AI 分析 → 执行确认 → 执行任务详情 → 审计记录
```

该闭环能够验证平台最核心的价值：AI 不直接替代人执行，而是帮助人理解现状、生成方案，并在人工确认后安全执行。
